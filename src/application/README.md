# Application — сценарии использования

Слой оркестрации TuneDraft: превращает проверенное намерение пользователя
в мутации модели. Домен по [layers.md](../../docs/specs/architecture/layers.md):
editing — координация мутаций и история undo/redo ≤ 3 шагов (№25).

## Текущий код: editing (этап 5)

Первый код слоя — чистый TS-контроллер редактора ([editing/](editing/)):

- [types.ts](editing/types.ts) — `EditMode` (`read`/`edit`, №40), `Selection`
  (ячейка №5 или колонка №35), union `EditorIntent` (все операции этапа 5 +
  undo/redo тулбара №37), `EditorState`, `EditorEffect` (запись в карман №26)
  и интерфейс `PocketWriter` — R2-инверсия: инфраструктурная возможность
  объявлена потребителем, реализацию (этап 7) вводит Entry-уровень.
- [history.ts](editing/history.ts) — история отмен снимками тетради ДО
  мутации: глубина ≤ 3 (№25, старейший вытесняется), redo-ветка (№37),
  новая мутация её обрывает.
- [controller.ts](editing/controller.ts) — конвейер `applyIntent`:
  интент → гейтинг режима (№40) → мутация модели → push undo (№25) →
  сброс redo (№37) → эффект кармана (№26). Отказ мутации (ModelResult err)
  не меняет тетрадь, не пишет историю и карман — кладёт предупреждение
  в состояние. Функция чистая: эффекты возвращаются списком.
- Тесты: [editing/__tests__/controller.test.ts](editing/__tests__/controller.test.ts)
  — jest-глобалы без импорта (R2-гард).

## Правила слоя

- Импортирует Domain напрямую (R2).
- Возможности Infrastructure получает только через интерфейсы,
  которые определяет сам (dependency inversion, R2–R3); сам Infrastructure
  напрямую не импортирует.
- Не знает про экраны, жесты и навигацию — это Entry Points.

## Что сюда кладём

Use cases: применение операций ячейки/колонки, вставка и перемещение
строк ленты, история отмены (№25), транзакционные границы мутаций.

## Чего здесь не будет

React-компоненты и обработчики жестов (Entry Points), JSON-файлы
и AsyncStorage (Infrastructure), сами правила модели (Domain).
