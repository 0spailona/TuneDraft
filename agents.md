# agents.md — правила работы для AI-агентов в TuneDraft

## Что это за проект

**TuneDraft** — Android-приложение: табулатурная тетрадь для бас-гитариста
(4 струны E–A–D–G, лады 0–24, экспорт в PDF A4 портрет).

**Текущее состояние: этап 2 завершён.** В репозитории: Expo-каркас (TypeScript) и слои
`src/` ([ADR-0003](docs/specs/decisions/0003-src-layer-directories.md)) — entry-файлы в корне
(`index.ts`, `App.tsx`), словарь строк `src/i18n/` (№31) и модель данных тетради
`src/domain/tabulature/` (типы, иммутабельные мутации с ошибками-значениями, детерминированные
id, фикстуры; юнит-тесты №34 зелёные). `src/application/` и `src/infrastructure/` —
пока README с правилами слоёв. Layout, ввод, хранение, рендер — этапы 3–8.
Новый код обязан ложиться в уже зафиксированную дисциплину (слои, спеки, ADR).

## Технологический стек (выбрано, см. КАРТА-ПРОЕКТА №10–№14, №23)

- **React Native + `@shopify/react-native-skia`** — рендер табулатуры на экране
- **Expo** (шаблон TypeScript) — каркас; минимальный Android — **API 24 (7.0)**
- **`react-native-gesture-handler` + `reanimated`** — жесты и анимация вне JS-потока
- **`expo-print` + `expo-sharing`** — экспорт HTML→PDF
- **`expo-file-system`** — тетради как JSON-файлы `tet-<id>.json`; **AsyncStorage** — настройки
- **Jest** — юнит-тесты модели данных и layout-движка обязательны (№34)

Сборка — локальный `.apk`: `npx expo run:android` или `eas build --platform android --local` (№13).
Команды каркаса: `npm run typecheck` (tsc --noEmit), `npm test` (jest-expo, №34),
`npm run lint` (ESLint: recommended + typescript-eslint + guard-правила слоёв —
`src/domain/` без фреймворков/UI/тестовых импортов (R1), `src/application/` без
фреймворков, entry-файлов и прямых импортов `infrastructure` (R2, превентивно),
`src/infrastructure/` без entry-файлов (R4-симметрия, превентивно)),
`npm run format` / `npm run format:check` (prettier; markdown и `docs/` исключены —
спеки форматируются вручную), `npm start` (Expo dev-сервер). Для `expo run:android` нужны JDK 17 и Android SDK
(`ANDROID_HOME`/`ANDROID_SDK_ROOT` → `~/Android/Sdk`); минимальный Android — API 24 (№23).

Политика версий пакетов: в `package.json` — диапазоны (`^`/`~`), фактические версии
фиксирует закоммиченный `package-lock.json` (воспроизводимая установка — `npm ci`).
Runtime-зависимости (`expo`, `react`, `react-native` и связанные) ведутся по версиям
Expo SDK; tooling (eslint/prettier/typescript-eslint) обновляется осознанно:
`npm outdated` → обновление → прогон `npm run lint && npm test`.

## Ключевой архитектурный принцип (№14)

**Модель и layout отделены от рендера.**

```
Модель (чистые данные: тетрадь → строки → колонки → ноты/черты/тексты)
        ↓
Layout-движок (чистый JS: колонки и ноты → координаты x, y)
        ↓                          ↓
Рендер Skia (экран)        Рендер HTML→PDF (expo-print)
```

Один layout-движок → экран и PDF всегда согласованы. Не дублируй геометрию
в двух рендерерах и не тащи I/O в модель/layout (правила слоёв R1–R6:
зависимости только вниз, Domain без I/O и фреймворков).

## Жёсткие правила

1. **Спеки — источник истины.** Расхождение спека и кода = баг (в коде или в спеке —
   решай по контексту). Спеки не генерируются из кода, а ведутся вручную.
2. **Обновляй спеки вместе с кодом.** Изменил документированное поведение —
   обнови спек в том же change; добавил/удалил файл спека — обнови `INDEX.md`.
3. **Разрешай маркеры `TODO: verify`** в том же change, что приносит код,
   к которому они относятся. Маркер, переживший появление своего кода, — дефект.
4. **ADR с `Status: Accepted` неизменяемы.** Новое решение = новый ADR +
   `Superseded by` в старом.
5. **Формат спеков — строго по шаблонам из [META.md](docs/specs/META.md)**
   (порядок секций, kebab-case имена, относительные ссылки из `docs/specs/`).
6. **Инварианты — только утвердительно** («всегда возвращает…», не «не должен…»).
7. **Язык интерфейса приложения — русский**; строки — через словарь, без хардкода (№31).
8. **Юнит-тесты (Jest) обязательны** для модели данных и layout-движка —
   критерий приёмки этапов 2–3 дорожной карты (№34).
9. **Фича вне MVP — не делай.** Список отложенного: воспроизведение, классическая
   нотация, палитра длительностей, drag-ввод по струне, 5-я струна, облако,
   альбомы, «поделиться PDF» из библиотеки, iOS, английский UI, темы, пинч-зум —
   см. §4 КАРТЫ-ПРОЕКТА. Модель при этом уже готова к части из них
   (`duration`, `albumId`, `version` — хранятся с первого дня).

## Порядок работы над задачей

1. Открой [docs/КАРТА-ПРОЕКТА.md](docs/КАРТА-ПРОЕКТА.md) — найди все решения (№NN), которых касается задача.
2. Открой [docs/specs/INDEX.md](docs/specs/INDEX.md) — найди спеки по типу задачи.
3. Правь код/спеки по правилам выше.
4. Прогони чек-лист валидации из [WORKFLOW.md §5](docs/specs/WORKFLOW.md).
5. Если принято архитектурное решение — оформи ADR (`decisions/_template.md`, следующий номер).

## Дорожная карта (кратко; полная — в КАРТЕ-ПРОЕКТА §3)

Этапы 0–10: инструменты → каркас Expo → модель данных → layout-движок →
Skia-рендер → ввод (меню ячейки/колонки, undo ≤ 3) → лента строк и скролл →
сохранение/библиотека → PDF-экспорт → локальный .apk → README и GitHub.
Каждый этап имеет критерий приёмки — сверяйся с ним перед завершением.
