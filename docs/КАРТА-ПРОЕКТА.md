# 🎸 TuneDraft — карта проекта

> **TuneDraft** — Android-приложение: табулатурная тетрадь для бас-гитариста.
> Этот документ — все решения, принятые при планировании.

---

## 1. Итоговые решения

| # | Тема | Решение |
|---|------|---------|
| 1 | Формат записи | **Табулатура** — базовый и единственный формат v1. **Классическая нотация** — гипотетически «когда-то очень потом» (после MVP и всех отложенных фич), без обязательств по срокам |
| 2 | Струны | **4 струны** (E–A–D–G) в v1. Модель хранит струны как **список MIDI-нот** → добавление 5-й струны (низкое B) потом = одна строка конфига |
| 3 | Лады | 0 (открытая) … 24 |
| 4 | Длительности | Поле `duration` в модели ноты **с первого дня** (по умолчанию — четверть). UI в v1 — **без ритма**; палитра длительностей — этап после MVP |
| 5 | Ввод нот | **Тап выделяет ячейку** (пересечение струны и колонки); вставка и правка — через **контекстное меню ячейки** (№21), вызываемое **в нижней части экрана** (панель на месте клавиатуры, №36). Следующий шаг — **«тяни по струне»** (drag, цифра лада едет за пальцем) |
| 6 | Вид на экране | **Лента строк** (по образцу **My Guitar Tabs**): документ = вертикальная последовательность **строк двух видов**. **Таб-строка** — система табулатуры (4 струны, ноты слева-направо). **Текст-строка** — текст, неограниченное количество, к нотам не привязан, многострочный. Между таб-строками можно вставлять сколько угодно текст-строк (и до первой, и после последней таб-строки — где угодно в ленте). **Текст колонки** — до **3 текстов**, привязаны к колонке (№35), рисуются **под таб-строкой** (№24). Бесконечный скролл |
| 7 | Вид при экспорте | **Листы A4 в портретной ориентации** («как бумажная тетрадь», выбор пользователя): та же лента строк (таб-строки + текст-строки) с разбивкой по листам; перенос строки на новый лист только по её границе. Системы короче — длинноты лечатся переносом систем, а не поворотом листа. Само приложение работает **в обеих ориентациях экрана** (№23) — портрет/альбом выбирается поворотом устройства |
| 8 | Экспорт | **Только PDF** |
| 9 | Воспроизведение | ❌ НЕ входит в MVP. MVP = правка + сохранение + экспорт |
| 10 | Стек | **React Native + Skia** (`@shopify/react-native-skia`) — выбор пользователя, осознанный |
| 11 | Жесты | `react-native-gesture-handler` + `reanimated`. **Жест = движение пальца по экрану, распознаваемое системой как команда** (в отличие от простого тапа). Для нашего редактора: тап — выделить ячейку/колонку и открыть контекстное меню (№21, №35), **вставка строк — кнопка «+» в левом углу** (№36), **лонг-тап по пустому месту** — быстрый путь вставить текст-строку (№36), **лонг-тап на начало строки → drag в корзину/крестик** — удаление строки (№36), **drag** — перемещение строк (№36), драг по струне — «перетащить цифру лада» (после MVP), пинч — зум (кандидат). Эти две библиотеки — стандартный связующий стек RN для жестов с плавной 60 fps-анимацией вне JS-потока |
| 12 | Каркас | **Expo** (шаблон TypeScript) |
| 13 | Сборка | **Локальный .apk**: `npx expo run:android` или `eas build --platform android --local` (gradle). Облако — опционально |
| 14 | PDF-механика | Единый **layout-движок** на чистом JS (ноты → координаты) + **два рендерера**: Skia (экран) и HTML→PDF через `expo-print` + `expo-sharing` (экспорт). Одинаковая геометрия — ноль дублирования логики |
| 15 | Инструменты | **WebStorm** (основная IDE), **Android Studio** (установит — нужна для SDK и локальной сборки apk) |
| 16 | Хранилище репозитория | GitHub, репозиторий пока пустой |
| 17 | Опыт разработчика | JS — хорошо, React — немного, PHP — немного; Android — новый |
| 18 | Тактовые черты | **В базовой версии (MVP)**: вставка через панель вставки в меню ячейки (№21), но черта **всегда занимает всю колонку**: тап по пустой ячейке → «черта» → **вся колонка становится колонкой-чертой** (вертикальная линия через все 4 струны). Если в колонке уже есть ноты (аккорд) — **вставка черты заблокирована**. **В колонке-черте текстов нет.** Такт **любой длины**, без привязки к длительностям (сумма не проверяется). Layout-движок не разрывает такт при переносе системы |
| 19 | ID объектов | У каждой ноты, черты, колонки и текста — **стабильный уникальный `id`** (генерируется при создании, не меняется). **Текст привязан к колонке по `columnId`** (а не по позиции и не к ноте — колонка объединяет одновременно играемые ноты, №35). **Удаление колонки каскадно удаляет её ноты и тексты** |
| 20 | Сетка и ячейки | Таб-строка = **сетка ячеек** («миллиметровка», по образцу My Guitar Tabs): **ячейка = пересечение струны и колонки; колонка = объединение ячеек** (в колонке — одновременно играемые ноты; вместо нот — цифры ладов). Базовая ширина колонки — **минимум 4 символа** (2 на номер лада + по 1 отступу слева/справа); **колонка раздвигается**, если текст не влезает; максимум — **12 символов** (порог запрета ввода текста, №24). **Ёмкость таб-строки**: пустая таб-строка создаётся целиком — всё пустое пространство экрана (~85% ширины) делится на минимальную ширину ячейки. Если строка не влезает (колонка раздвинулась или вставились колонки) — **пока в конце есть пустые колонки, сокращаем строку за счёт их удаления; когда пустых нет — создаём новую таб-строку и переносим хвост на неё**. Пустая ячейка — самостоятная сущность (пауза, «не играть») |
| 21 | Контекстное меню ячейки | **Тап — выделить ячейку** → меню в **нижней панели** (№36). Пустая ячейка → сразу **панель вставки**: кнопки ладов **0–24** (цифры, в несколько рядов) + **тактовая черта** (занимает всю колонку, №18). Занятая ячейка → **правка** (та же панель ладов, но **без** черты — цифра лада меняется, `id` сохраняется) + **удалить ноту** (ячейка очищается, остаётся) |
| 22 | Версия формата | Поле `version` в JSON тетради — **с первого дня** (страховка будущих миграций формата) |
| 23 | Ориентация и платформа | Поддерживаются **и портрет, и альбом**. **При повороте экрана перенос систем пересчитывается** под новую ширину (re-flow: в альбоме влезает больше колонок; модель хранит данные, а не координаты — пересчёт бесплатен; PDF и превью считаются по своей ширине независимо). Минимальный Android — **API 24 (Android 7.0)**: это пол текущего стека (Expo SDK 54+ ставит `minSdkVersion 24` по умолчанию, Skia требует ≥ API 21, RN 0.86 — ≥ 24); ниже — только откатом версий стека. Выше поднимать без нужды не нужно. Тестовое устройство — планшет **Acer Iconia X12**: на этапе 0 проверить в «Настройки → О планшете», что Android ≥ 7.0; если ниже — тестировать на эмуляторе, `minSdk` не поднимать. Поднять позже точечно легко (`expo-build-properties`, некоторые библиотеки просят 26+) |
| 24 | Тексты колонки | Рисуются **под таб-строкой** (стопкой, до 3), выровнены по своей колонке; колонка под них раздвигается (№20). Если текст достиг **максимума ширины** колонки (12 символов, №20) — **ввод запрещается с предупреждением** (не обрезаем, не переносим) |
| 25 | Undo | **Отмена до 3 шагов** в MVP. Отменяется **любая мутация модели**: ноты, черты, тексты, колонки, строки ленты |
| 26 | Сохранение | **«Сохранить»** — пишет финальную версию. **«Закрыть»** — переспрашивает, сохранять ли; **явный отказ — чистит карман сразу** (карман спасает только от аварий — сворачивание, убийство процесса, — а не от осознанного «нет»). **Автосохранение — да**, но в **промежуточный карман** (черновик): **один на приложение** — в нём последняя редактируемая, но не сохранённая тетрадь (одновременно открыта может быть только одна тетрадь — и для чтения, и для редактирования; режимы — №40: тап по карточке = чтение, переключатель «Править»/«Чтение» в редакторе). **Карман пишется после каждого действия**. **Файл `tet-<id>.json` физически создаётся при первом «Сохранить»** (не сразу после ввода имени — иначе «закрыть без сохранения» оставляло бы пустую тетрадь-мусор в библиотеке; карман, как обычно, страхует от аварий). При запуске приложения: карман не пуст → переспрос; «да» → версия из кармана сохраняется в постоянную, карман чистится; «нет» → карман просто чистится. Если тетрадь из кармана удалена из библиотеки — восстановление пересоздаёт файл `tet-<id>.json` |
| 27 | Ввод текста | **Текст колонки** — добавление и правка через **контекстное меню колонки** (№35): появляется стандартная текстовая клавиатура. **Текст-строка — модальное окно**; текст может быть **многострочным** |
| 28 | Виртуализация | Длинная лента: рендерится **окно вокруг экрана** (видимые строки ± запас), а не весь документ |
| 29 | Хранение | **JSON-файлы** (expo-file-system) — тетради: переносимы, бэкапируемы; **имя файла — стабильное, по id**: `tet-<id>.json` (видимое имя тетради живёт только внутри JSON — переименование файла не ломает). **AsyncStorage** — настройки приложения |
| 30 | Библиотека тетрадей | В карточке — **имя + превью** (**первая система** — таб-строка до переноса; рендерится при «Сохранить», кэшируется в файл `tet-<id>.png` рядом с JSON). Карточки отсортированы **по дате изменения, свежие сверху**. **Битый JSON** → карточка с пометкой «повреждена»: открыть нельзя, удалить можно. Опции: **переименовать, удалить, экспортировать** — контекстное меню по кнопке справа; **«экспортировать» в MVP = JSON-бэкап**: файл кладётся **в отдельную папку рядом с .apk** (выбор пользователя; видна через файловый менеджер/USB — точную папку уточнить на этапе 7, буквального «рядом с .apk» Android не даёт, ближайшее — внешнее хранилище приложения). **Импорт JSON — после MVP** (PDF-экспорт уже есть из редактора, №8; «поделиться PDF» из библиотеки — тоже после MVP). В развитии: размер превью (большое/маленькое/без), дата редактирования, «форк» (отправить в Telegram/контакты). Тетради группируются в **альбомы — после MVP** (модель с первого дня хранит `albumId` — альбомы не потребуют миграции; библиотека с карточками — в MVP) |
| 31 | Язык интерфейса | **Русский** — базовый; **английский** — добавляемая опция (строки интерфейса — через словарь, без хардкода) |
| 32 | Шрифты и темы | Цифры ладов — **моноширинный** шрифт (база). Заголовки и тексты — через **темы**: шрифтовые + цветовые. **MVP — одна жёстко зашитая тема**; система тем (выбор шрифтов/цветов) — после MVP |
| 33 | PDF-колонтитул | **Заголовок тетради на каждом листе PDF**: правый верхний угол, мелкий шрифт. Плюс **номер страницы**: внизу по центру, мелко. Лист — **A4 портрет** (№7) |
| 34 | Тесты | **Юнит-тесты обязательны**: модель данных и layout-движок покрываются тестами (Jest; критерий приёмки этапов 2–3) |
| 35 | Колонка и её контекстное меню | **Колонка** — сущность модели: объединяет ячейки четырёх струн; в колонке — одновременно играемые ноты (аккорды разрешены) + до 3 текстов, **либо колонка целиком является тактовой чертой** (№18). **Тап по заголовку/верхней зоне колонки — выделить колонку** → отдельное контекстное меню (в нижней панели, №36): **вставить колонку слева / справа** (пустая), **очистить колонку** (удалить все ноты и тексты, колонка остаётся), **удалить колонку** (полностью, со всем содержимым — каскад, №19), **добавить текст** (стандартная клавиатура; если у колонки уже 3 текста — **запрет с предупреждением**, по аналогии с №24). Правка текста — через это же меню. Меню ячейки (№21) и меню колонки — разные. **Меню колонки-черты** (№18): «очистить» = убрать черту (останется пустая обычная колонка), вставить слева/справа и «удалить» — как у обычной колонки |
| 36 | Управление строками ленты | **Вставка строк — кнопка «+» в левом углу экрана** → мини-выбор типа строки: **таб-строка или текст-строка** (текст-строку можно и лонг-тапом по пустому месту ленты). **Перемещение** — drag: можно перемещать все строки на странице. **Удаление** — лонг-тап на начало строки → переместить её в нарисованную **корзину/крестик**; **начало таб-строки = ключ-ручка**: в начале каждой таб-строки рисуется **басовый ключ 𝄢** (традиционен для бас-гитары; также маркер начала системы) — он же служит ручкой захвата для drag и удаления. **Начало текст-строки = ручка-полоска слева** (появляется при захвате). **Удаление такта или всей таб-строки** — выделить колонку и **распространить выделение** (как в тексте), затем удалить; **такт = диапазон от одной тактовой черты до следующей; черт нет — такт = вся строка**. Контекстные меню ячейки/колонки открываются **в нижней части экрана, где обычно клавиатура** (не модальное окно). **Drag и корзина — в составе MVP** (этап 6, вместе с лентой строк) |
| 37 | Тулбар редактора | **Сохранить, Закрыть, Отмена (Undo ↶), Вернуть (Redo ↷), Экспорт PDF**. Undo = «Отменить» — шаг назад (до 3 шагов, №25); Redo = «Вернуть» — отменить отмену (если передумали). Стандартная пара в любом редакторе |
| 38 | Шаблон новой тетради | Новая тетрадь открывается не пустой: **текст-строка «название»** (предзаполнена именем из диалога создания), **текст-строка «описание»** (пустая) и **одна пустая таб-строка** |
| 39 | Навигация | **Стартовый экран — библиотека**. Системная кнопка «Назад» (Android): в редакторе = «Закрыть» с переспросом о сохранении (№26), в библиотеке = выход из приложения. Ради этого контракта в `app.json` выключен predictive back gesture (`predictiveBackGestureEnabled: false`) — система не перехватывает жест Назад, обработка полностью в приложении |
| 40 | Режимы чтения и правки | **Тап по карточке в библиотеке — открыть тетрадь для чтения** (основной сценарий: открыть и играть); **новая тетрадь — сразу в режиме правки** (создали — значит, будем записывать). В редакторе кнопка **«Править» / «Чтение» — переключатель**: в любой момент сменить режим в обе стороны (меню и панели ввода появляются только в правке). Открыта всё равно только одна тетрадь (№26) |

## 2. Архитектура

```
┌─────────────────────────────────────────────────────────┐
│                     СЛОИ ПРИЛОЖЕНИЯ                     │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  UI (React Native)                                      │
│  ┌─────────────────────────────────────────────┐        │
│  │ Экран библиотеки: карточки (имя + превью    │        │
│  │ tet-<id>.png), сортировка по дате; тап —    │        │
│  │ чтение (№40); опции: переименовать /        │        │
│  │ удалить / экспортировать JSON; альбомы —    │        │
│  │ потом (albumId в модели уже есть)           │        │
│  │ Экран редактора: лента строк (таб + текст), │        │
│  │ тап ячейки/колонки → меню в нижней панели;  │        │
│  │ «+» слева → вставка строки (тип: таб/текст) │        │
│  │ лонг-тап по пустому месту → текст-строка;   │        │
│  │ drag строк (ручка 𝄢 / полоска), корзина     │        │
│  └──────────────────┬──────────────────────────┘        │
│                                                         │
│                     │                                   │
│                                                         │
│  МОДЕЛЬ ДАННЫХ (чистый TS)                              │
│  Тетрадь = { version, name, albumId, строки }           │
│  Строки (в любом порядке):                              │
│    таб-строка → сетка: колонки × ячейки струн           │
│    колонка = ноты, играемые одновременно                │
│              (аккорды), или тактовая черта;             │
│              тексты колонки ≤ 3                         │
│    текст-строка → Текст (без нот, многострочный)        │
│  Нота = { id, stringIndex: 0–3, fret: 0–24,             │
│           duration }                                    │
│  Текст = { id, columnId } — привязка к колонке;         │
│  удалили колонку → ноты и тексты удалены                │
│  (каскад)                                               │
│  Струны = [E1, A1, D2, G2] (MIDI) — расширяемо          │
│                                                         │
│                     │                                   │
│                                                         │
│  LAYOUT-ДВИЖОК (чистый JS)                              │
│  колонки и ноты → координаты (x, y); тексты             │
│  колонки рисуются ПОД таб-строкой; колонка              │
│  раздвигается под текст; ёмкость строки: ~85%           │
│  экрана / мин. ячейка; не влезает — пустые колонки      │
│  в конце убираются, хвост — на новую строку;            │
│  такт не рвётся                                         │
│        ┌──────────────┴──────────────┐                  │
│        ▼                             ▼                  │
│  РЕНДЕР Skia (экран)          РЕНДЕР HTML→PDF           │
│  <Canvas>, линии струн,       expo-print: A4 портрет    │
│  басовый ключ — ручка,       заголовок + номер          │
│  цифры ладов, такты, тексты   страницы на листах        │
│                                                         │
│  ХРАНИЛИЩЕ: тетради — JSON-файлы tet-<id>.json          │
│  (expo-file-system); превью карточек — tet-<id>.png;    │
│  настройки — AsyncStorage;                              │
│  карман автосохранения (один на приложение,             │
│  пишется после каждого действия)                        │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**Ключевой принцип:** модель и layout отделены от рендера.
Один движок раскладки → экран и PDF всегда согласованы.
